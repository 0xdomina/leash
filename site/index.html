Outcomes are unverified unless returned by the transaction RPC. Refresh checks state and activity once; there is no automatic polling. Allowance is a spending limit, not the contract balance.

A prompt cannot spend what the contract refuses.

Most agent setups hand a model an API key and trust a client-side check to stop it. Leash moves the limit into the chain: the agent holds a function-call key scoped to one contract and one method, and the contract itself rejects any spend over the cap.

Typical API-key agent

Limits live in the client

  • Where it is enforcedApplication code or a rate limiter in the agent process, outside any shared authority.
  • Failure modeA bug, a prompt injection, or a modified client bypasses the check. The key still works.
  • Key scopeA long-lived secret with full account access. Revocation means rotating the key everywhere.
  • Spend ceilingWhatever the client decides. Daily totals are kept in a database that the agent can reach.
  • AuditLogs written by the same process that might be compromised.

Leash on NEAR

Limits live in the contract and the VM

  • Where it is enforcedContract code executed by every NEAR validator. The per-transaction cap and the 24 hour daily cap are checked on-chain before any transfer.
  • Failure modeAn over-cap call panics and reverts. The attempt is recorded as a failed transaction with the reason.
  • Key scopeA function-call key can be limited to your Leash contract and its spend method. Inspect view_access_key_list separately to verify the agent has no broader access.
  • Spend ceilingOwner-set caps stored in contract state. The agent cannot raise them; set_caps requires the owner key.
  • AuditEvery decision is a public transaction with a hash, verifiable without trusting Leash or the agent host.

Limit spending. Keep the risks visible.

Caps apply to calls through this contract. Correct deployment and key scope matter. The inspector does not verify access keys, contract upgrades, or available balance.

Per-payment cap

No single spend can exceed the owner-set per_tx_cap. An over-cap call reverts on-chain with the reason in the receipt.

24-hour window cap

Spend accumulates in a 24 hour window tracked in contract state. Once daily_cap is reached, further spend is refused until the window rolls over.

Scoped permission keys

Restrict the agent key to spend on your contract. Other access keys can weaken this boundary; inspect the full key list independently. The configured owner controls cap changes.

Start with a read. Deploy for your agent.

These examples only read get_config. The public Testnet contract belongs to its configured owner; it is not a wallet you can adopt or control.

  1. Inspect the public contractRun a read-only example. get_config returns the configured accounts, caps, stored window spend, window start, and nonce. It does not return an effective remaining allowance.
  2. Deploy your own contract on TestnetReview the source and initialize your deployment with your owner and agent accounts. Do not fund the public example as your wallet.
  3. Restrict the agent keyScope a function-call key to your contract and its spend method. Remove other agent access keys as appropriate and verify the key list. Keep the owner key off the agent host.
  4. Integrate payments separatelyThe call is spend(to, amount), with amount in yoctoNEAR. Handle rejected calls and inspect transfer receipts. These read-only examples do not sign transactions.
// Cargo.toml under [dependencies]:
// reqwest = { version = "0.12", features = ["blocking", "json"] }
// serde_json = "1"
// Save as src/main.rs, then run: cargo run
use serde_json::{json, Value};
use std::time::Duration;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = reqwest::blocking::Client::builder()
        .timeout(Duration::from_secs(10)).build()?;
    let response: Value = client
        .post("https://rpc.testnet.near.org")
        .json(&json!({
            "jsonrpc": "2.0", "id": 1, "method": "query",
            "params": {
                "request_type": "call_function",
                "finality": "final",
                "account_id": "leash-0445ff.testnet",
                "method_name": "get_config",
                "args_base64": "e30="
            }
        }))
        .send()?.error_for_status()?.json()?;
    if response.get("error").is_some() {
        return Err("RPC request failed".into());
    }
    let bytes: Vec<u8> = serde_json::from_value(
        response["result"]["result"].clone()
    )?;
    let config: Value = serde_json::from_slice(&bytes)?;
    println!("{}", serde_json::to_string_pretty(&config)?);
    Ok(())
}
// Node.js 20+. No packages or keys required.
// Save as read-config.mjs, then: node read-config.mjs
// Also valid TypeScript with ES2022 + DOM libraries.
const response = await fetch(
  "https://rpc.testnet.near.org",
  {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    signal: AbortSignal.timeout(10_000),
    body: JSON.stringify({
      jsonrpc: "2.0", id: 1, method: "query",
      params: {
        request_type: "call_function",
        finality: "final",
        account_id: "leash-0445ff.testnet",
        method_name: "get_config",
        args_base64: "e30="
      }
    })
  }
);
if (!response.ok) throw new Error("RPC HTTP failure");
const payload = await response.json();
if (payload.error) throw new Error("RPC request failed");
const bytes = payload.result?.result;
if (!Array.isArray(bytes) || !bytes.every(
  n => Number.isInteger(n) && n >= 0 && n <= 255
)) throw new Error("Invalid RPC bytes");
const config = JSON.parse(
  new TextDecoder().decode(Uint8Array.from(bytes))
);
console.log(config);
